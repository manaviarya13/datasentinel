# DataSentinel reproduction\n\nThis repository implements a research reproduction of **DataSentinel: A Game-Theoretic Detection of Prompt Injection Attacks** (IEEE S&P 2025). It follows the paper's known-answer detector and alternating attacker/defender formulation. The repository does not claim to have reproduced the paper's numerical results.\n\nReproduction of the IEEE S&amp;P 2025 DataSentinel research paper on game-theoretic detection of prompt injection attacks.\n\n## Method\n\nThe detector asks a detection LLM to repeat a secret key while ignoring the supplied data. If the key appears in the generated output, the sample is classified as clean; otherwise it is classified as contaminated.\n\nTraining simulates a strong attacker that knows the actual key. Its objective combines key-token cross-entropy and backend desired-output cross-entropy. For minimax training the attacker can edit only the shared separator `z` in `x_c = x_t || z || s_e || x_e`. Each round alternates GCG updates to `z` with QLoRA detector updates using clean and contaminated samples.\n\nThe realistic adaptive evaluation attacker is a separate procedure. It does not receive the actual key, samples surrogate keys from the keyspace, and optimizes the whole initial contaminated input for the paper's 50 GCG iterations. Do not conflate its threat model or editable token region with minimax training.\n\n## Implementation status\n\nImplemented now: known-answer inference interface, explicit training/evaluation attacker objectives, generic GCG coordinate search, training separator constraint, alternating loop orchestration, QLoRA model loader that requires explicit adapter parameters, schema-driven local data loaders, and FPR/FNR and standard classification metrics.\n\nStill unresolved for a faithful model-scale run: the paper/released author source does not specify minimax GCG search values or how to combine gradients across Mistral and LLaMA3 tokenizers for a shared textual separator. It also does not publish QLoRA adapter rank/alpha/dropout/target modules or optimizer details. These are recorded in [implementation decisions](docs/IMPLEMENTATION_DECISIONS.md); the paper-scale config leaves them unset. There is no automatic dataset downloader or complete task-specific preprocessing yet.\n\n## Environment setup\n\nThe dependency-free detector and algorithm utilities need Python 3.10 or newer and pytest for tests. Windows PowerShell:\n\n```powershell\npython -m venv .venv\n.\.venv\Scripts\Activate.ps1\npython -m pip install -e .\npython -m pip install pytest\npytest -q\n```\n\nThe current execution environment is Python 3.14 on Windows with no PyTorch, Transformers, PEFT, BitsAndBytes, or visible CUDA GPU. Do not install model-training dependencies or download multi-gigabyte checkpoints until the compute gate in [compute requirements](docs/COMPUTE_REQUIREMENTS.md) has been resolved. The QLoRA loader imports heavy libraries lazily and refuses incomplete adapter config.\n\n## Modes\n\n- **Smoke test:** synthetic stub model and tiny token examples; no research claims. Run `python scripts/run_smoke_test.py`.\n- **Reduced scale:** same algorithm components with smaller user-provided local models/data and explicitly marked engineering reductions. See `configs/reduced_scale.yaml`.\n- **Paper scale:** original models, data protocol, and training/evaluation settings. See `configs/original_paper.yaml`; unresolved fields must be sourced before running.\n\nKeep outputs from the modes in separate run directories and include the config, seed, model revisions, dataset manifests, and setting provenance in each result record.\n\n## Tests\n\n```powershell\npytest -q\npython scripts/run_smoke_test.py\n```\n\nTests use stub models only for software behavior. They do not validate model behavior or demonstrate reproduction of the research results.\n\n## Documentation\n\n- [Paper and authors' repository audit](docs/PAPER_REPRODUCTION_AUDIT.md)\n- [Implementation decisions and unresolved details](docs/IMPLEMENTATION_DECISIONS.md)\n- [Dataset protocol and acquisition status](docs/DATASETS.md)\n- [Dataset provenance and split conflicts](docs/DATASET_PROVENANCE.md)\n- [Explicit dataset protocols](docs/DATA_PROTOCOL_CONFLICTS.md)\n- [Shared-separator GCG analysis](docs/SHARED_SEPARATOR_GCG.md)\n- [QLoRA settings audit](docs/QLORA_REPRODUCTION.md)\n- [Baseline accounting](docs/BASELINES.md)\n- [Run manifests and result artifacts](docs/RUN_MANIFEST.md)\n- [Compute requirements](docs/COMPUTE_REQUIREMENTS.md)\n- [Reproduction report](docs/REPRODUCTION_REPORT.md)\n- [Stage 2 gap report](docs/STAGE2_GAP_REPORT.md)\n\n## Citation\n\n```bibtex\n@inproceedings{liu2025datasentinel,\n  title={DataSentinel: A Game-Theoretic Detection of Prompt Injection Attacks},\n  author={Liu, Yupei and Jia, Yuqi and Jia, Jinyuan and Song, Dawn and Gong, Neil Zhenqiang},\n  booktitle={IEEE Symposium on Security and Privacy},\n  year={2025},\n  doi={10.1109/SP61157.2025.00250}\n}\n```\n
