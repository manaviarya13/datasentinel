# Dataset sources and preprocessing status\n\n## Paper protocol\n\nThe paper uses seven datasets, each with train and test splits:\n\n| Paper task | Dataset | Role |\n|---|---|---|\n| Duplicate sentence detection | MRPC | Target and injected task in 7×7 test matrix |\n| Grammar correction | JFLEG | Target and injected task in 7×7 test matrix |\n| Hate detection | HSOL | Target and injected task in 7×7 test matrix |\n| Natural language inference | RTE | Target and injected task in 7×7 test matrix |\n| Sentiment analysis | SST-2 | Target and injected task in 7×7 test matrix |\n| Spam detection | SMS Spam | Target and injected task in 7×7 test matrix |\n| Text summarization | Gigaword | Target and injected task in 7×7 test matrix; also DataSentinel training source |\n\nThe detector's minimax training set `D` contains 500 Gigaword **training split** examples paired with the paper's short-summary instruction. Evaluation samples 100 test examples per target task and another 100 per injected task. The paper reports a fixed random seed but does not provide its value in the text inspected. The train/evaluation split boundary must remain at the dataset-provided splits; no evaluation sample may enter `D`.\n\nFor the existing-attack evaluation, the paper forms 100 target tasks and 100 injected tasks for each of the seven task types (49 target/injected combinations). It samples 100 pairs for each of the seven attacks applicable to general task pairs (five general heuristic attacks, Universal, NeuralExec), yielding 34,300 contaminated examples. Availability Attack and PLeak each create 100 contaminated examples per target task, adding 1,400; the paper reports 35,700 total. The paper does not fully describe whether the 100 target and 100 injected task samples are required to be mutually disjoint when sampled from the same source split; that sampling detail remains unresolved and must be pinned to author source/data artifacts rather than guessed.\n\nThe paper calls out a training/evaluation distinction: minimax `D` is 500 Gigaword training examples, while Section V-A describes evaluation samples from test splits. The current authors' repository configs use several different splits, not just JFLEG. See [dataset provenance](DATASET_PROVENANCE.md) and [protocol conflict analysis](DATA_PROTOCOL_CONFLICTS.md); no split is silently treated as equivalent.\n\n## Acquisition and preprocessing\n\nNo dataset is bundled in this repository and no files are downloaded automatically. Dataset source identifiers, versions, licenses, normalization, and exact label-to-output mapping were not fully specified by the DataSentinel paper. The authors' repository has task configs naming the same sources/splits and task instructions in `data/system_prompts/`. `load_task_instructions` reads those exact target/injected prompt files from a user-supplied checkout; it fails if a file is missing and does not substitute another prompt. Pin that checkout to a commit in the run manifest before paper-scale data can be declared verified. Do not substitute a similarly named corpus or infer labels silently.\n\nThe local loader accepts CSV, JSON, and JSONL only when input/output field names are explicitly supplied. It stores dataset name and source split with each normalized record. It does not fetch or transform raw upstream corpora. This is an ingestion boundary, not yet a complete reproduction preprocessing pipeline.\n\n## Version/license register\n\n| Dataset | Source/version | License | Status |\n|---|---|---|---|\n| MRPC | Paper names MRPC; exact release and author-side preprocessing to pin | Not established from paper | Pending source verification |\n| JFLEG | Paper names JFLEG; exact release and author-side preprocessing to pin | Not established from paper | Pending source verification |\n| HSOL | Paper names HSOL; exact release and author-side preprocessing to pin | Not established from paper | Pending source verification |\n| RTE | Paper names RTE; exact GLUE release/preprocessing to pin | Not established from paper | Pending source verification |\n| SST-2 | Paper names SST-2; exact release/preprocessing to pin | Not established from paper | Pending source verification |\n| SMS Spam | Paper names SMS Spam; exact collection/preprocessing to pin | Not established from paper | Pending source verification |\n| Gigaword | Paper names Gigaword; exact version/preprocessing to pin | Not established from paper | Pending source verification |\n\nThe paper’s test protocol samples 100 per task but does not state an auditable numeric seed. Until the authors' scripts or archived data manifests establish this, chosen seeds and exact filtering rules must be recorded as implementation choices. The in-repo `sample_examples` and `split_examples` helpers are deterministic utilities; they do not imply that the paper’s exact sample set has been reconstructed.\n\n## Leakage safeguards\n\n- Training uses the Gigaword training split; evaluation uses each task's test split as stated by the paper.\n- Every normalized row retains its source split and optional source ID.\n- Deterministic split helper asserts disjoint non-empty IDs.\n- Any future derived train/validation/test split must persist IDs and sampling seed in the run manifest.\n- The separate injected task selected from `D` during each minimax round is a training task; the paper reports that `D` does not overlap evaluation target/injected tasks.\n\n## Deviations\n\nAt this stage only schema-driven local ingestion and dataset inventory exist. No source data have been acquired, no paper sample has been reconstructed, and no dataset result is reported.\n
