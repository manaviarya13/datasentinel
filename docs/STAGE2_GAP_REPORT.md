This preserves the paper objective and shared textual separator; proposal/search mechanics are not claimed as the authors' exact algorithm.\n3. **Dataset conflict:** Three explicit protocols now exist in `data/protocols.py`: paper text, current authors repository, and documented engineering. Only shared `z` token text is editable. The detector update minimizes `-J1 + beta J2`; each outer update uses a contaminated batch and a clean batch of `b_out=2`, for 500 updates each of three rounds. CE is sequence-summed per paper equations.\n\nAdaptive evaluation remains separate: Section V-D1 has the two manual variants and an unknown-key GCG attacker, one surrogate key per iteration, 50 iterations, `gamma=1`, full contaminated text editable. These are not used as training's separator optimizer. The cited GCG method supplies top-k first-order proposals and exact candidate scoring; its universal method discusses aggregation, but neither it nor the DataSentinel paper provides a demonstrated Mistral/LLaMA3 gradient alignment rule for this objective.\n\n## Paper-specified versus unresolved GCG settings\n\n| Item | Evidence / status |\n|---|---|\n| Training outer schedule | `r=3`, `n_in=10`, `b_in=8`, `n_out=500`, `b_out=2`; V-A/Algorithms 1–3. |\n| Training GCG steps | Exactly 10 inner updates per round, each on a minibatch of 8 pairs.
