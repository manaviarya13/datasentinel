PyTorch, Transformers, PEFT, BitsAndBytes, and Hugging Face Datasets are not installed. `nvidia-smi` is unavailable and no GPU was visible through the current environment. Windows CIM queries were denied, but PowerShell/.NET reported RAM. CUDA and PyTorch compatibility therefore cannot currently be established.\n\nNo model or dataset download and no full training run has been launched. A paper-scale 7B/8B setup requires far more than the currently available memory without a supported accelerator. QLoRA reduces trainable memory but still requires loading large 4-bit weights, activations, optimizer state for adapters, and GCG candidate batches. The project intentionally does not estimate run time from a missing GPU.\n\n## Execution modes\n\n### Mode A: Smoke test\n\n- Synthetic inputs and deterministic stub models.\n- Exercises detector decisions, shared-separator constraints, alternating order, checkpoint/config interfaces, and metrics.\n- Uses no scientific result data and produces no reproduction claim.\n- Configuration: `configs/smoke_test.yaml`.\n\n### Mode B: Reduced-scale experiment\n\n- Same objective, GCG coordinate mechanics, minibatch update order, and QLoRA path as paper.\n- Smaller locally available causal models, data counts, GCG settings, and iteration counts are engineering deviations and must appear in every result manifest.\n- Current environment lacks PyTorch and a visible GPU; only dependency-free algorithm utilities are presently executable.\n- Configuration: `configs/reduced_scale.yaml`; user must provide local model paths and a compatible supported runtime.\n\n### Mode C: Paper-scale reproduction\n\n- Mistral-7B detector, LLaMA3-8B-Instruct backend, original datasets/sample counts, 3 rounds, 10 inner updates/round, 500 outer updates/round, QLoRA, and complete evaluation matrix.\n- Use a CUDA-capable Linux environment with supported PyTorch, Transformers, PEFT and BitsAndBytes versions; model access terms and any gated checkpoint authorization must be satisfied by the operator.\n- Exact QLoRA adapter values and GCG search settings are not published in the DataSentinel paper/released training source and remain explicitly unresolved. The original config blocks these values instead of treating guesses as paper facts.\n- Configuration: `configs/original_paper.yaml`.\n\n## Memory and compatibility gate\n\nBefore model access or installation, record GPU model/VRAM, CUDA runtime/driver, PyTorch build, available system RAM, exact model revisions, and the selected dependency lock. A model-scale run must refuse to start when the required 4-bit path or QLoRA adapter config is unavailable. Do not install a large ML stack into Python 3.14 or begin downloads without first resolving platform support and the intended accelerator environment.\n\nNo model memory or time estimate is reported because GPU and precise runtime details are unavailable. A 7B detector plus 8B backend should be budgeted as a multi-model GPU workload; GCG adds many candidate forward evaluations and can dominate the optimization phase.\n
