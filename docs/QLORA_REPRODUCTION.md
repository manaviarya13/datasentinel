# QLoRA reproduction settings audit\n\n## Evidence boundary\n\nDataSentinel v4 states that the detector is fine-tuned with QLoRA. Section V-A reports Mistral-7B, outer learning rate `2.5e-5`, outer batch size `2`, and `n_out=500` updates per round; Algorithm 1 reports three rounds. Algorithm 3 samples a contaminated minibatch and a clean minibatch separately, each with `b_out=2`, and applies gradient descent to `-J1 + beta*J2`. Thus a paper outer update uses two clean and two contaminated examples (four sequence losses total), not one combined batch of size two. Neither the paper nor Appendix C fills in adapter-level QLoRA details for the main minimax run.\n\nThe authors' current `QLoraModel.py` is an inference loader. It loads a 4-bit base with NF4, double quantization and BF16 compute, then loads a previously trained PEFT adapter. This is evidence of released inference-time base loading only. It does not show the training LoRA config, optimizer, scheduler, accumulation, or training precision. The official repository README currently says detector fine-tuning scripts are not released.\n\n## Setting register\n\n| Setting | Paper-specified | Repository evidence | Reproduction treatment |\n|---|---|---|---|\n| Detector | Mistral-7B | `mistralai/Mistral-7B-v0.1` config | Paper-family setting; exact revision must be pinned. |\n| QLoRA | Yes | PEFT adapter inference supported | Method specified, training script absent. |\n| Base quantization | Not specified | 4-bit | Inference-derived implementation choice, not paper claim. |\n| Quant type | Not specified | NF4 | Inference-derived implementation choice. |\n| Double quantization | Not specified | Enabled | Inference-derived implementation choice. |\n| Quant compute dtype | Not specified | BF16 | Inference-derived implementation choice. |\n| LoRA rank / alpha | Not specified | No training values surfaced | Unresolved; paper-scale config must block without a sourced choice. |\n| Target modules | Not specified | Not exposed by inference wrapper | Unresolved. |\n| Dropout | Not specified | Not exposed | Unresolved. |\n| Optimizer | Not specified | Not exposed | Unresolved. Let `J1` and `J2` be the respective minibatch means. Minimize `-J1 + beta*J2` using gradient descent on trainable adapter parameters. Do not use an ordinary binary classifier loss or a static contaminated dataset in place of the alternating generated batches. The implementation's causal LM helper computes prompt-plus-key in one tokenization pass, masks prompt tokens, rejects prompt/key tokens crossing its offset boundary, and rescales model mean CE to token-summed CE. Real tokenizer alignment and QLoRA updates remain untested.\n\n## Engineering recipe gate\n\nThe reduced-scale config currently carries explicit example LoRA values and labels them `engineering_choice`; those are not claimed to match the paper. Before using them, a compatible ML runtime, actual local models, and optimizer configuration must be recorded. For a real-model experiment, prefer one declared, standard PEFT recipe with its full fields pinned in the run config; report the method as a QLoRA engineering approximation.
